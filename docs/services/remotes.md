# Remote templates

A Nexus remote is a stand-alone application that registers itself with the registry on startup and exposes one or more federated modules. Three templates ship; `bnx generate remote` picks the right one based on the framework you select.

| Template | Repo | Framework |
|---|---|---|
| Angular | `nexus-remote-templat` | Angular 19 |
| Vue | `nexus-remote-templat-vue` | Vue 3 |
| React | `nexus-remote-templat-react` | React 18 |

For end-to-end depth, see [Angular remote](../guides/guide-angular-remote.md), [Vue remote](../guides/guide-vue-remote.md), [React remote](../guides/guide-react-remote.md).

## Angular remote (`nexus-remote-templat`)

```
nexus-remote-templat/
├── src/
│   ├── app/remote-entry/entry.component.ts   # @NexusRemote / @NexusComponent / @Component
│   ├── main.ts                                # provideNexusRemote(...)
│   └── ...
├── federation.config.js                       # native-federation shim
├── federation.config.json                     # generated by nexus-build
├── angular.json
├── package.json                               # scripts: prebuild=nexus-build
├── Dockerfile
└── nginx.conf
```

Build: `npm run build`. The `prebuild` script runs `nexus-build`, which scans for `@NexusRemote` and writes `federation.config.json`. The Angular CLI then runs `ng build` and produces `dist/<name>/browser/`.

## Vue remote (`nexus-remote-templat-vue`)

```
nexus-remote-templat-vue/
├── src/
│   ├── app.vue            # local standalone shell
│   ├── entry.vue          # exposed as ./RemoteEntry
│   └── main.ts            # registerNexusRemote(...)
├── index.html
├── vite.config.ts         # nexusVite plugin
├── package.json           # vite + @vitejs/plugin-vue
├── Dockerfile
└── nginx.conf
```

Build: `npm run build`. Vite + the `nexusVite` plugin produce `dist/index.html`, `dist/assets/*`, `dist/remoteEntry.json`, and `dist/catalog.json`.

## React remote (`nexus-remote-templat-react`)

```
nexus-remote-templat-react/
├── src/
│   ├── app.tsx            # local standalone shell
│   ├── entry.tsx          # default export = exposed component
│   └── main.tsx           # registerNexusRemote(...)
├── index.html
├── vite.config.ts         # nexusVite plugin
├── package.json           # vite + @vitejs/plugin-react
├── Dockerfile
└── nginx.conf
```

Build: `npm run build`. Same outputs as Vue, plus React 18 hydration.

## Self-registration

When a remote container boots, the framework adapter posts the remote to the registry. The container must have:

```yaml
environment:
  REGISTRY_INTERNAL_URL: http://registry:8670
  NEXUS_TOKEN: ${NEXUS_TOKEN}
  PUBLIC_URL: /remotes/<name>/remoteEntry.json
  UPSTREAM_URL: http://<this-container>:80
```

The registry stores the record and broadcasts `remotes_changed`. The gateway hot-updates its route table; every connected host browser tab learns of the new route.

## Docker build

The `@bimo-dk/*` packages are public on npmjs.com — no auth token or BuildKit secret is needed.

```bash
docker build -t my-remote .
```

Dockerfile excerpt:

```dockerfile
# syntax=docker/dockerfile:1.7
FROM ghcr.io/bimo-dk/nexus-base:latest AS build
WORKDIR /app
COPY package.json package-lock.json* ./
RUN npm ci --prefer-offline
COPY . .
RUN npm run build

FROM nginx:1.27-alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
```

## Scaffolding

```bash
bnx generate remote
? Remote name (camelCase): checkout
? Route path (kebab-case): checkout
? Framework: angular | vue | react
```

`bnx generate remote` clones the matching template, substitutes `__REMOTE_NAME__`, `__REMOTE_ROUTE__`, the port in `package.json` and `vite.config.ts`, and gives you a ready-to-build remote.
