# Remotes

Repo: [`nexus-remote-templat`](https://github.com/Bimo-dk/nexus-remote-templat) — used as a scaffold, not as a base image.

A **remote** is an independent Angular 19 app that exposes exactly one module — `./RemoteEntry` — which the host mounts at a route. Each remote has its own repo, its own CI, its own Docker image, and (in production) its own URL.

```
src/app/remote-entry/entry.component.ts   <- the exposed module
  ↓ exposes as ./RemoteEntry
host (any route)                          <- the host mounts it
```

## Anatomy of the template

```
nexus-remote-templat/
├── federation.config.js          # withNativeFederation(...) — library convention
├── federation.config.json        # generated by nexus-build
├── angular.json                  # Angular CLI config
├── nginx.conf                    # serves dist/ + /health
├── Dockerfile
├── src/
│   ├── index.html, main.ts, bootstrap.ts
│   └── app/
│       ├── app.component.ts      # standalone-run only (not exposed)
│       ├── app.config.ts
│       ├── app.routes.ts
│       └── remote-entry/
│           └── entry.component.ts   # YOUR CODE — @NexusRemote() + @Component
```

`__REMOTE_NAME__` and `__REMOTE_ROUTE__` are placeholders that `bnx generate remote` substitutes when it clones the template.

## The only file you should care about

```ts
// src/app/remote-entry/entry.component.ts
import { Component, signal } from '@angular/core';
import { NexusRemote } from '@bimo-dk/nexus-build';

@NexusRemote()                  // name + route auto-inferred (or pass options)
@Component({
  selector: 'app-remote-entry',
  standalone: true,
  template: `<h2>Hello from checkout</h2>`,
})
export default class EntryComponent {
  readonly count = signal(0);
}
```

That's the contract. Add child routes, services, lazy modules — anything Angular allows — but **this file's class** is what the host mounts.

## How federation config is generated

Hand-editing `federation.config.json` is something you should never do. The build pipeline:

```
ng build
  ├─ prebuild  (npm-script)
  │    └─ nexus-build
  │         ├─ scan src/**/*.ts for @NexusRemote
  │         ├─ resolve name / route / exposeAs
  │         └─ write federation.config.json
  └─ ng build    (reads federation.config.js -> federation.config.json)
```

`@bimo-dk/nexus-build` resolves the remote's identity in this order:

1. Decorator option — `@NexusRemote({ name: 'checkout' })`
2. `package.json#name` if it is valid camelCase (also strips an `@scope/` prefix)
3. The class name — `CheckoutComponent` → strip `Component`/`Entry` → camelCase → `checkout`

Route is derived from the name (`checkoutPage` → `checkout-page`) unless `@NexusRemote({ route })` is passed.

See [`@bimo-dk/nexus-build`](../packages/nexus-build.md) for full options.

## Bootstrap

```ts
// src/bootstrap.ts
import { bootstrapApplication } from '@angular/platform-browser';
import { provideNexusRemote } from '@bimo-dk/nexus-runtime';
import EntryComponent from './app/remote-entry/entry.component';

bootstrapApplication(EntryComponent, {
  providers: [
    provideNexusRemote({
      entry: EntryComponent,
      configDefaults: {
        registryUrl: 'http://localhost:3000',
        nexusToken: 'dev-token',
      },
    }),
  ],
});
```

`provideNexusRemote(...)` does only the minimum a remote needs:

- Reads `/assets/config.json` and merges over `configDefaults`
- Registers a `SelfRegisterService` that POSTs (or PUTs) the remote's config to the registry at bootstrap

So when a remote container starts in production it announces itself automatically — no manual `bnx publish` needed if the registry already knows it (config writeback handles updates).

## Federation config

`federation.config.js` is library boilerplate — leave it untouched:

```js
const { withNativeFederation, shareAll } = require('@angular-architects/native-federation/config');

module.exports = withNativeFederation({
  // name + exposes are read from federation.config.json
  // shared block is set by your shared() decision
  ...require('./federation.config.json'),
  shared: { ...shareAll({ singleton: true, strictVersion: true, requiredVersion: 'auto' }) },
});
```

## Bundle size discipline

Because every remote ships its own Angular runtime in dev mode (and *shares* it in prod via `singleton: true`), avoid:

- Importing the whole `@angular/material` in every remote — share via the host or load lazily.
- Pulling `rxjs` operators with deep imports (`rxjs/operators/map` is gone in v7) — use the standard tree-shakeable imports.
- Including locale files for every locale; pick what your app needs.

`shareAll({ singleton: true, strictVersion: true })` lifts every shared dep to a single instance across host + all remotes — but only the ones the host already bundled. If your remote uses `@angular/cdk` and the host doesn't, you ship it inline.

## Docker

```dockerfile
FROM node:22-alpine AS builder
COPY package*.json .npmrc ./
RUN --mount=type=secret,id=node_auth_token,required=true \
    NODE_AUTH_TOKEN=$(cat /run/secrets/node_auth_token) \
    npm install --legacy-peer-deps
COPY . .
RUN npm run build:prod

FROM nginx:alpine
COPY --from=builder /app/dist/<name>/browser /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
```

`nginx.conf` for a remote is just a static-file server plus `/health`. It does not proxy anything.

## Standalone run

Run the remote on its own — useful for hot-reload development:

```bash
npm install
npm start    # ng serve --port 8700 --host 0.0.0.0
```

Open http://localhost:8700 and you see the `AppComponent` (`src/app/app.component.ts`), which is a thin wrapper around the entry component for standalone runs. The host never sees this — it only loads `./RemoteEntry`.

## Adding a remote — three workflows

1. **`bnx generate remote`** — recommended. Clones this template, substitutes placeholders, drops it in a new folder. See [workflows/create-remote](../workflows/create-remote.md).
2. **Fork manually** — for an existing repo you want to convert. Copy `federation.config.js`, add the dev-dep `@bimo-dk/nexus-build`, annotate your entry component with `@NexusRemote()`.
3. **Add via portal only** — for a *running* remote that you only need to make visible. Open `/remotes/new`, fill in name + URL. No code change.
